# Active Search Sim-to-Real 1차 Domain Randomization 학습 및 벤치마크 결과

## 1. 실험 개요
* **목적:** 실제 환경(Sim-to-Real) 적응을 위해 시각적·기하학적 도메인 랜덤화를 적용한 데이터셋으로 ACT 정책을 학습하고, 성능 및 문제점을 검증
* **적용된 랜덤화 요소 (`domain_rand`):**
  * **조명:** 광원 세기, 색온도, 그림자 각도 무작위화
  * **테이블 텍스처:** 실제 책상 기반 변형 텍스처(`white_dominant`) 적용
  * **큐브 재질:** 3D 프린팅 PLA 질감 및 노멀맵 적용
  * **방해물(Distractors):** 비(非)빨간색 잡동사니 1~3개 무작위 배치
  * **로봇 팔 색상:** 3D 프린팅 파트 파란색 계열 적용
  * **카메라 외적 지터(Extrinsics Jitter):** 좌/우 손목 카메라 독립적으로 회전 `±2.5°`, 위치 `±3.0mm` 적용
* **데이터셋 규모:** 총 **74개** 에피소드 (유효 74/74, 음수 각도 `Theta < 0°` 41개(55.4%) / 양수 각도 `Theta >= 0°` 33개(44.6%), 각도 범위 `-53.3° ~ +52.0°`, 평균 스테레오 추정 오차 `9.06mm`)

## 4. GUI 실패 패턴 및 원인 분석

### GUI 단건 테스트 관찰 결과
* **`0°` 정면 실패:** 스캔 없이 큐브 앞으로 내려가 전진하지만, **그리퍼 턱으로 큐브를 밀어버리며** 파지 실패
* **`+30°` 양수 각도 실패:** 스캔 후 큐브 앞까지 접근하고 전진하지만, **그리퍼 방향이 몇 도 더 돌아가서** 큐브가 그리퍼 사이로 들어오지 못함

### 핵심 원인
1. **데이터 수집기 vs 신경망(ACT) 간의 카메라 지터 정보 비대칭:**
   * 데이터 수집 시 스크립트(`search_and_pick_policy.py`)는 시뮬레이터에서 **지터가 적용된 실제 카메라의 3D Pose**를 읽어 스테레오 3D 좌표를 계산하므로, `±2.5°` 지터가 있어도 큐브를 정확히 집어냄.
   * 반면 **ACT 정책은 RGB 이미지와 관절 각도(`qpos`)만 입력받기 때문에 해당 에피소드의 카메라 지터 각도를 알 수 없음.**
   * 결과적으로 `±2.5°` 지터(30cm 거리 기준 **약 1.3cm** 위치 오차)가 이미지와 정답 Action 간의 기하학적 매핑을 흔드는 노이즈로 작용하여, 오프라인 L1 Loss는 낮아졌으나(평균값 수렴) 3cm 큐브 파지에 필요한 ±1cm 이내 정밀 정렬에 실패함.
2. **소규모 데이터(74 에피소드) + 넓은 랜덤화 폭:**
   * 표본 수가 적은 상태에서 큰 지터와 시각적 랜덤화가 동시에 적용되어, 특히 표본이 더 적었던 `Theta >= 0°` 구간에서 특정 방향의 정렬 편향(bias)이 남음.
