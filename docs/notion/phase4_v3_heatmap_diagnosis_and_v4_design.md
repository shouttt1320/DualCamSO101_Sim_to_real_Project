# v3 실물 히트맵 정량 진단 및 v4 모델 수정 방향

## 1. 배경 및 진단 목적

`v3` 모델(`dinov2_vits14_reg` + `15x20` 보조 히트맵 헤드)은 시뮬레이션 환경에서 큐브 위치 히트맵과 `Top Half Masked` OOD(Out-of-Distribution, 학습 분포 외 입력) 문제를 해결했다. 그러나 `v3`의 보조 히트맵은 학습 손실에만 쓰일 뿐 ACT(Action Chunking with Transformers) 디코더의 행동 입력으로 직접 전달되지 않아, 정책이 여전히 하단 파란 그리퍼 모양 등 배경 단서에 의존하는 문제가 남아 있다.

`v4`에서는 히트맵에서 추출한 **큐브 보임 확률(`p_vis`)과 정규화 중심 좌표 `(u, v)`**를 요약 토큰으로 만들어 트랜스포머에 직접 주입할 계획이다. 이 구조가 실물에서 효과를 내려면, **시뮬레이션으로만 학습된 히트맵이 실물 영상에서도 큐브 위치와 유무를 정확히 맞춰야 한다.** 이를 사전에 검증하기 위해 `v3` 체크포인트(`Epoch 247`, `real_wall_twin/policy_best.pth`)와 대안 헤드 구조를 실물 데이터에서 정량 진단했다.

## 2. 진단 데이터 및 용어 정의

### 평가 데이터 (실물 데이터 학습 0회, Zero-Shot 평가)
- **실물 녹화 에피소드 (`real_robot/episode_0000~0002.hdf5`)**: 시뮬레이션에 없는 원목 바닥 환경, 총 `476`프레임
  - 큐브 보임 (`GT = 1`): `355`프레임 (접근 구간 `빨간 픽셀 < 8,000`: `155`장 / 잡기 직전 근접 구간 `>= 8,000`: `200`장)
  - 큐브 없음 (`GT = 0`): `121`프레임 (`빨간 픽셀 <= 15`)
- **실물 흰 책상 대기 화면 (`standby_real_L`, `standby_real_R`)**: 실제 운용 환경(`OBSERVATION_POSE`)에서 큐브 없이 촬영한 좌/우 카메라 순수 화면 2장 (`GT = 0`)
- **비교용 직결 헤드 학습 데이터**: 시뮬레이션 `real_wall_twin` 45개 에피소드에서 균등 추출한 `900`프레임 (실물 데이터 미사용)

### 용어 설명
- **`GT` (Ground Truth)**: HSV 빨간색 마스크로 계산한 실제 큐브 유무 및 중심 좌표 정답.
- **`p_vis` (Visibility Probability)**: 히트맵 전체 `15x20` 패치 중 최댓값에 시그모이드를 취한 값(`sigmoid(max_logit)`). 모델이 "화면에 큐브가 보인다"고 판단하는 확률 (`0~1`).
- **`TPR` (True Positive Rate, 큐브 검출률)**: 실제 큐브가 있을 때(`GT=1`) `p_vis >= 0.5`로 맞춘 비율.
- **`TNR` (True Negative Rate, 빈 화면 정답률)**: 실제 큐브가 없을 때(`GT=0`) `p_vis < 0.5`로 맞춘 비율.
- **`β` (Temperature, 온도 계수)**: Soft-argmax 계산(`softmax(β * logit)`) 시 분포를 얼마나 날카롭게 만들지 결정하는 배수.
- **`pos_weight`**: 이진 교차 엔트로피(BCE) 손실에서 양성(큐브 패치) 오차에 곱하는 가중치.
- **중심 거리 `r(0,0)`**: 화면 정중앙 `(0, 0)`에서 예측 좌표 `(u, v)`까지의 평균 거리. `GT`보다 작으면 예측점이 화면 중앙으로 끌려가는 현상(중앙 쏠림)이 발생했음을 의미한다.

## 4. 핵심 발견 사항

1. **`v3`의 Soft-argmax 중앙 쏠림 확인**
   - `v3`에서 기본 `softmax`(`β=1.0`)를 사용하면 배경 패치에 퍼진 확률 때문에 예측 좌표가 화면 중앙으로 끌려간다(`r(0,0)`: 정답 `0.673` -> 예측 `0.516`). 이로 인해 접근 구간 오차가 `80.4px`까지 커졌다.
   - `β=3.0`으로 분포를 날카롭게 만들자 `v3`의 접근 구간 오차가 `32.0px`로 절반 이상 감소했다.

2. **`input_proj`(512-D) 우회 + 동결 `dinov2_vits14_reg`(384-D) 직결 효과**
   - `v3`의 히트맵 헤드는 시뮬레이션 액션 학습으로 변형된 `input_proj`(512-D) 뒤에 붙어 있어, 시뮬에 없는 실물 배경에서 노이즈가 커졌다.
   - 히트맵 헤드를 동결된 `dinov2_vits14_reg` 패치 출력(384-D)에 직접 연결하자, 실물 데이터 학습 없이도 접근 구간 오차가 **`15.7px` (중앙값 `9.8px`, 패치 1칸의 절반 수준)**, 잡기 직전 근접 구간 오차가 **`22.1px`**로 크게 개선되었다.

3. **빈 화면 오탐(`p_vis` 상승)의 직접 원인: 과도한 `pos_weight`**
   - 기존 `v3`와 방식 B에서는 `15x20` 패치 BCE 손실에 `20~30배`의 `pos_weight`를 적용했다. 이로 인해 모든 패치 로짓의 기준선(bias)이 위로 들뜨면서, 큐브가 없는 흰 책상 우안 화면에서도 `p_vis = 0.646` (`v3`), `0.892` (방식 B)로 오탐이 발생했다.
   - 패치 BCE를 `pos_weight=1.0` 균형 손실로 바꾸고 `max_logit`에 별도 BCE를 결합하자(방식 C), 흰 책상 대기 화면 `p_vis`가 **좌안 `0.119` / 우안 `0.128`**로 안정적으로 억제되었다.

4. **남은 한계 및 유의점**
   - 시뮬레이션에 없는 **주황빛 원목 바닥**(`real_robot/ep0~2`의 큐브 없는 프레임)에서는 방식 C도 `TNR 24.0%`로 배경 오탐이 남는다.
   - 흰 책상 대기 화면 표본이 현재 좌/우 2장으로 적으므로, `v4` 학습 후 실물 테스트 단계에서 빈 책상·그리퍼 단독·검은 상자 단독 프레임을 수십 장 추가 수집해 `TNR`과 `p_vis` 분포를 재확인해야 한다.
   - 접근 구간 평균 오차(`15.7px`)가 중앙값(`9.8px`)보다 큰 것은 소수 프레임에서 좌표가 크게 튀는 이상치(outlier)가 존재함을 뜻한다.

## 5. 확정된 `v4` 수정 방향

진단 결과와 아키텍처 검토 내용을 모두 반영해 다음 4가지 축으로 `v4`를 구현한다.

### 5-1. 모델 구조 (`detr_vae.py`)
1. **히트맵 헤드 직결**: `cube_heatmap_head`를 `input_proj`(512-D) 뒤가 아니라 **동결 `dinov2_vits14_reg` 패치 특징(384-D)에 직결**한다 (`Conv2d(384, 1, kernel_size=1)`).
2. **Spatial Softmax 큐브 요약 토큰 추가 (카메라당 1개, 총 2개)**:
   - 학습 가능한 temperature `β` (초기값 `1.5`, 양수 보장)로 가중치 맵 `attn_map = softmax(β * hm_logit)` 계산.
   - `attn_map`은 **`detach()`**하여 액션 손실의 gradient가 히트맵 위치 예측을 망치지 못하게 차단한다.
   - 카메라별 요약 토큰 생성:
     - `cube_feat = (attn_map.detach() * proj_feat).sum(dim=(2, 3))` (`proj_feat` 경로로는 gradient를 유지해 파지에 필요한 특징을 학습)
     - `cube_coord = [p_vis, u, v]` (3차원) -> `cube_coord_proj`(MLP, 마지막 층 **0으로 초기화**)로 512-D 투영 후 `cube_feat`에 가산
     - 트랜스포머 입력 시퀀스 앞단에 `[latent, proprio, cube_L, cube_R, image_patches...]` 형태로 결합 (`additional_pos_embed`를 4개로 확장, 신규 `[2:4]`는 **0으로 초기화**하여 `--resume` 시 `v3` 성능에서 안정 출발).
3. **지름길 학습(Shortcut) 및 오탐/이상치 방어 (학습 전용)**:
   - **미탐 방어 (15% 드롭아웃)**: 학습 중 15% 확률로 큐브 요약 토큰을 `0`으로 마스킹.
   - **좌표 오차 및 이상치 방어**: `(u, v)`에 기본 가우시안 노이즈 `±0.05` (가로 약 `16px`)를 섞고, 추가로 **5% 확률로 큰 오차 `±0.25`**를 주입.
   - **오탐 방어 (12% 가짜 큐브 주입)**: 큐브가 실제로 없는 프레임(`gt_vis == 0`) 중 12% 확률로 `p_vis = Uniform(0.6, 0.95)`와 무작위 `(u, v)`를 주입해, 정책이 이미지 패치와 교차 확인하여 가짜 신호를 무시하도록 훈련.

### 5-2. 보조 손실 함수 및 체크포인트 선정 (`train.py`)
1. **균형 패치 BCE (`pos_weight = 1.0`)**: 배경 로짓 들뜸으로 인한 실물 빈 화면 오탐을 방지한다.
2. **카메라별 개별 `p_vis` BCE**: 기존 양안 통합 `max` 1개가 아니라 `vis_logit_L`, `vis_logit_R` 각각에 대해 개별 카메라 정답(`gt_vis_L`, `gt_vis_R`)으로 BCE 손실을 걸어 좌/우 `p_vis` 확률을 직접 보정한다.
3. **체크포인트 저장 기준 변경**: `policy_best.pth` 저장 기준을 `val_total_loss`에서 **`val_l1`**으로 변경한다. (단, 최종 모델 비교는 시뮬 18포인트 벤치마크와 실물 테스트 성공률로 판단)

### 5-3. 데이터 증강 정리 (`dataset.py`)
- `RedProtectedBorderErasing`에서 **하단 중앙 그리퍼 보호 영역을 제거**하고 빨간 큐브 영역만 보호한다. 시뮬과 실물의 그리퍼 화면 비율 차이를 정책이 외우지 않도록 하기 위한 조치다.

## 6. 구현 후 검증 계획
1. **학습 및 시뮬레이션 벤치마크**: `v4` 학습 후 18포인트 능동 탐색 벤치마크(`04_eval_active_search.py`) 및 `Top Half Masked` OOD 테스트 비교.
2. **실물 빈 화면 추가 검증**: 실제 흰 책상 환경에서 큐브 없는 대기·그리퍼 이동·검은 상자 단독 프레임 20~30장을 수집해 `v4`의 `p_vis` 분포와 `TNR` 재측정.
3. **실물 로봇 배포 테스트**: `deploy_real_robot.py`로 탐색(Search) -> 접근(Approach) -> 파지(Grasp) 실물 성공률 비교.
